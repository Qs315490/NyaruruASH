# 现状与证据链

> 本文只记录**测量过的东西**，并把「已验证事实 / 已否证假设 / 未决问题」严格分开。
> 每条都给出数字与复现入口（脚本或 `runs/*/loop-report.json`）。
> 更新本文时：**结论变了要改数字，假设被否证要保留在「已否证」里**——那份清单的价值
> 就是阻止我们重复付同一笔代价。

## 一句话

自进化循环的**管道全部打通、并且逐项在真机验证过**；但**唯一的学习信号来源**
（IDM 对语料帧打的伪标签）经多次实测**不可用**，因此 π 目前学不到「好行为」。

### 1. 输入护栏（`env/cdp_backend.py` + `memory/agent.js`）

| 能力 | 验证方式与结果 |
|---|---|
难度自动应答 | 真机：选项 `['按下简单难度按钮','按下普通难度按钮','\C[18]按下困难难度按钮']`；`resolve_difficulty()` → 选项消失、`Scene_Map`、map/hp 不变 |

GAME OVER | 真机：`_selectBox._selected=up`、`STATIC_TEXT_CONTINUE_YES`（读取存档）放行，`CONTINUE_NO` 拒绝；角色死在陷阱的那一帧实测 `_invincibleTime=0`、`_staggerTime=36`、`hp=0` |
道具弹窗 | `Scene_ItemObtain`：游戏源码 `pressOk = this.popScene`（ok 只关窗）；真机 `press_ok → True (35 ms)` 后 `Scene_Map` |

### 2. 循环管道

- `infer → retrieve → bootstrap` 多轮跑通；**每轮报告在 bootstrap 开始前落盘**（死在 bootstrap 的 run 也留得下数据）。
- **K 的触发条件被验证**：同一区域 ≥3 条 CDP 抓帧轨迹 → 簇被保留 → 触发。
  实测 `house-001/2/3` 三段 → `key_moments 1`、回合 `233` 步（此前恒为 120）。
- **语料裁剪有效**：实机帧对语料的最优余弦 `0.8249 → 0.9375`（裁掉叠加层 20% + 还原 4:3）。
- 检索随之开始选中速通视频（此前 4 条全是录制）。
- 录制边录边落盘（硬杀可恢复）；`pretrain-idm` 支持打包后的 mmap 目录形式。

## 二、已实测否证（不要再走）

| 假设 | 测量 | 结论 |
|---|---|---|
语料帧间隔太短（运动太小） | 步长 1/2/3 时 noop 占比 `50.9 / 51.1 / 51.8%` | ✗ 与间隔无关 |
视频叠加层/取景是唯一差距 | 裁剪+4:3 后余弦 0.94，但**同一实机帧仍进不了保留簇** | ✗ 不够 |
用视频管线做数据增强来适配 | 语料 noop `43.4% → 91.9%`，**自己的录制 `2.2% → 59.6%`** | ✗ 把模型弄坏了（代码已删） |
视频偏青蓝是原因 | 按通道线性校准后 noop `43.5% → 48.0%` | ✗ 无改善 |
取景/比例（压扁 vs 中心裁） | 9% → 最高 33%，**均低于多数类基线 56%** | ✗ 不解释 |
换更强的编码器（冻结 DINOv2 + MLP 头） | 跨场景 `45.1%` vs 基线 `50.4%` | ✗ 同样不泛化 |
帧间隔/颜色/取景之外「视频里没有那个地方」 | 视频里**确实有**同一片森林（画面已核对） | ✗ 不是「没有」 |

## 三、核心阻塞：IDM 跨场景不泛化

判定方式：**训练 3 个屋子录制 → 在留出的 `human-001` 上测**（跨场景，不是同场景随机划分）。

```
ImpalaCNN 从零训练        准确率 45.5%   多数类基线 50.4%   ← 等于瞎猜
冻结 DINOv2 + MLP 头      准确率 45.1%   多数类基线 50.4%   ← 同样等于瞎猜
对照：同场景内随机划分      91.6%（旧回放）                  ← 之前的乐观数字来自这里
```

**但任务本身有信号**（所以不是「不可学」）：

```
                       标签=不动      标签=有动作
旧回放                变化中位 0.33    1.12
录制 house-002        变化中位 0.35    1.30      ← 动作帧变化是 3~4 倍
两分布重叠            74 ~ 78%                  ← 天花板约 70~80%，不是 95%
```

⇒ 瓶颈是**场景多样性/泛化**，不是任务不可学、也不是编码器不够强。

**后果（机制链）**：

```
IDM 在语料（未见场景）上退化为「答先验」≈ 50% noop
   ↓ π 用 BC 模仿这个分布
π 学成「尽量不动」  ← 观察到；独立测量：20 秒里位置只变 2 次、最后 11 秒完全静止
```

D^R（每轮实际用于训练 π 的检索结果）里**可信数据只占 38%**（合计视频 47 条 / 录制 29 条）；
agent 在小屋时是 4/4 录制（那时标签可信，2.2% noop），一走出覆盖范围就变成 3/4 视频。

## 四、未决 / 未验证

1. **自监督预训练（最该试的方向，但探针没跑通）**
   用 68k 帧、跨几十个场景、**不需要标签**的语料学「什么样的变化算运动」。
   探针 `scripts/probe_ssl_idm.py` 的结果**既未支持也未否证**：
   时序判别 loss 卡在 `0.6931`（= ln2，一步没动），随后动作头 `NaN`。
   修通前不要把它当作结论。
2. **K 在 map 6/8/14 沉默**：实机帧与最近语料帧余弦 `0.9577`，但**那一帧本身**在 HDBSCAN 里
   就是噪声（`label=-1`）——即「余弦近」不等于「落在簇里」。
3. **四个新动作的「效果」未验证**：`special/ult/weapon_switch/item` 只验证了「键到位」
   （引擎 `keyMapper` 证实），实际效果需要战斗场景。

## 五、三条可选方向（停止实验，等决策）

1. **修通自监督探针再判断**：诊断判别器为何一步不动（打印 trunk 输出方差）、NaN 来自哪一步。
   判据不变：**跨场景留出准确率必须显著高于多数类基线**。便宜、判据硬。
2. **换一条不依赖 IDM 的路**：π 只用 self-play 的**真实动作标签** + K 记忆，不用语料伪标签。
   这会改变论文 Alg 4，属偏差，需明确确认。
3. **接受当前能力边界**，把项目定位为「护栏 + 记忆 + 检索」的框架，学习信号部分标注为待解决。
