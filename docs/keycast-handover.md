**未来帧是可用的**：ASH 里 IDM **在自博弈轨迹上训练（动作已知）**，然后**被应用到语料视频**

**为什么这改变了结论**：按键的证据是它的**后果**（跳跃弧线/挥击/冲刺），而后果**在按键之后**；
4 fps 的一对帧只覆盖 0.25 s，**恰好截断后果**；而先前所有实验（含 K 扫描）**都只回看过去**。

实测（视频1，30 fps，线性探针，16×16/帧，时序切分）：

| 时间窗 | macro-F1 | ON 位 | **动作键均值** |
|---|---|---|---|
| 只有当前帧 | 0.205 | 0.237 | 0.126 |
| 过去 8 → 当前 | 0.246 | 0.267 | 0.195 |
| **当前 → 未来 8 帧（±0.27 s）** | **0.578** | **0.654** | **0.678** |

⇒ **只用未来最好；加过去更差；窗口越长越差。**
⇒ 第 4 节那 14 条排除**全部是在「因果」表述下做的**，它们证明的是
**「因果单帧对 + 4 fps 拿不到动作键」**，**不是「任务不可能」**。

**跨视频这一道门：验过了，没过，但结论已比先前精确得多。**

| | 状态 | 数字（macro-F1 / 动作键） |
|---|---|---|
| **同视频内** | ✅ **可学** | 0.594~0.730 / **0.68~0.86** |
| **跨视频** | ❌ **未迁移** | 0.00~0.09 / 0.00~0.33 |

跨视频试过三次干预**全部无效**：**增强**（亮度/对比度/位移/逐视频标准化）、

**弱正信号**：未归一化时两折的**动作键均值 0.30~0.33** ⇒ **部分动作键能迁移一点**，

## 1.5 数据布局：一个视频一个文件夹（2026-09-26 新增）

此前一支视频的东西散在 **3 个目录、27 个文件**里，元数据还分在 cells 与 mapping 两个文件 ✗
现在统一为 **`data/videos/<视频ID>/`**：

```
data/videos/BV19s4y1y7un/
    video.mp4                  源视频（硬链接，不占额外空间）
    meta.json                  ← 统一元数据（见下）
    labels.npz                 tick 对齐的按键标签
    corpus-4fps.npy            256² 语料帧（IDM 训练用）
    frames-30fps.npy           96² 灰度 @30fps（未来窗工作用）
    frames-30fps-color.npy     可选
    frames-30fps-gamearea.npy  可选（裁游戏区）
    features-dino.npy          可选
```

**`meta.json`** 字段（2026-09-26 修正两处）：

| 字段 | 含义 |
|---|---|
| `id` | 视频 ID（＝文件夹名） |
| `video` | **pack 内的真实文件名**（`"video.mp4"`）——**不是**迁移前的旧文件名；指向不存在的文件会被 `validate_meta()` 报出 |
| `source_file` | 出处文件名（`"BV....mp4"`），仅作溯源 |
| `size` | 帧尺寸 `[w, h]`（`ffprobe` 读出，用于校验其他矩形是否越界） |
| **`game_area`** | **游戏画面在帧内的矩形**，两个角点 `[[x0,y0],[x1,y1]]`（原生像素）——裁掉叠加层用 |
| `panel` / `panel_size` | 按键面板位置与尺寸（**面板相对坐标**的基准） |
| `style` | `"bright"`（球式，按下变亮）/ `"bluekey"`（键盘式，按下变蓝） |
| `cells` / `dir_proto` | 细胞坐标 / 方向九宫格（面板相对） |
| `mapping` | 细胞 → **游戏动作** |

**`game_area` 必须实测**（各视频不同：720p 带分栏的与 1080p 的不在一处），**不许猜**——
猜坐标正是本项目吃过亏的地方（曾把「游戏画面中间」当成面板，量出「73% 像素在帧间变化」）。
`validate_meta()` 会**报告**缺失/越界/角点顺序反了的 pack（不硬失败，新视频还没测）。

**当前状态**：`video 1/2/4 已实测`；**`BV1Am4y1t7Sv` 的 game_area 未测**（校验器会报出）✓

产物**全部可选**——新视频从「`video.mp4` + 一个带 panel/game_area/mapping 的 meta.json」开始即可。

**代码入口**：`src/ash/data/video_pack.py`
`load_meta() / save_meta() / artifact() / artifact_path() / stem_of() / migrate() / list_packs() / validate_meta()`
- **`artifact()` 读取（有旧路径回退）／`artifact_path()` 写入（永远进 pack）** —— 写入侧**故意没有回退**，
  否则新产物会继续落在旧位置、迁移永远做不完；
- **`stem_of()`：视频 ID 取自 pack 的「目录名」**（pack 内文件固定叫 `video.mp4`，
  按文件名推导会把每支视频都叫成 `video`——标注器刚迁移后就踩了这个坑，且它只对绝对路径失效，
  因为主流程 `.resolve()` 过 `--video`；已修 + 回归测试钉死）
**`artifact()` 在 pack 缺失时回退到旧的散落路径** ⇒ 未迁移的视频照常可用 ✓
`migrate(stem)` 幂等，大数组用**硬链接**（实测同 inode，零额外磁盘）✓
标注器**优先读 pack**，保存时**双写**（pack 的 meta.json + 旧的 cells/mapping）——
**陈旧的 pack 比没有 pack 更糟**，所以过渡期两份一起写 ✓

**旧位置的 28 个文件已删除**（20 个大数据文件 + 8 个 cells/mapping JSON，删除前逐个核对内容已在 pack 里）；
`data/video-src/` 空目录已移除。**磁盘不释放也不丢数据**——pack 内是硬链接。

**测试**：`tests/test_video_pack.py`（14 项，钉死：元数据往返、两个 legacy 文件必须**合并**读取、

## 5. 三条可复用的正面发现

1. **接口必须保留空间运动**：全局池化特征相减**不含**左右信息（0.503 ≈ 随机），
   **像素差含**（0.575~0.637）。任何用「池化后相减」当运动信号的方案都会静默失效。
2. **低分辨率反而更好**：可用的信号是**大尺度背景滚动**，不是角色细节；
   把画面裁到角色附近会**降到随机**。
3. **预训练骨干确实优于随机初始化**（0.000→0.173）——方向没错，只是天花板低。

## 7. 踩过的坑（下一个接手的人必读）

1. **每支视频的布局都要单独测**：面板位置、键帽样式（球 / 键盘键帽）、分辨率（720p/1080p）都不同。
   **先裁一帧看，别猜坐标**——按 720p 的坐标去猜 1080p 的面板，采到的是**游戏画面中间**，导致「73% 像素在帧间变化」。
2. **键帽有两种按下样式**：`style: "bright"`（球式，变亮）与 `style: "bluekey"`（键盘式，**变蓝**）。
   用错规则会得到 `tapped 95%`、`61% 不可表达`这种荒唐数字。
3. **大小阈值必须按面板尺寸缩放**：720p 的键帽面积上限 1600 px，1080p 键帽约 1600~2000 px，
   照抄会**一个键帽都取不到**（且完全静默）。
4. **坐标空间要用视频原生像素**：写死 1280×720 会让 1080p 视频的面板框**跑到画面外**（拖不到边）。
5. **`np.save` 覆盖正在读取的文件是一扇单向门**：失败时会先把文件截断成只剩头部（曾因此丢掉一份 2.8 GB 的语料）。
6. **可变帧率的源要用 `-frames:v` 明确帧数**：否则 `fps` 滤镜会在尾部补重复帧，标签与语料整体错位 52 s。
7. **同一规则只修一处会复发**：本轮工作出现过 4 次（拖动防护、面板尺寸、映射保存/加载、映射过滤）。
   **改规则时，先搜它的所有使用点。**
8. **「恰好正确的默认值」会掩盖缺陷**：视频1 的 `panel_size` 恰好等于默认值，所以缺字段一直没暴露。
9. **警告文案要跟着行为一起改**：`dir_proto` 为空对键盘式视频是**正常**的，
   而旧警告写着「directions will not be decoded」——**描述旧行为的警告比没有警告更糟**。
10. **游戏状态**：`scripts/keep_paused.py` 可保持暂停（无人操作时角色会被打死）；
    服务退出后游戏可能停在暂停态，恢复方式见 `AGENTS.md` 第 6 条。
